YOUR DATA

Privacy Policy

Effective and last updated: November 6, 2026

This policy describes the current personal-use MVP, Pearl's Health Tracker (also labeled IRON / OURA), maintained by the owner of the PearlDD/Oura-agent repository. Contact: dwy0618@gmail.com.

1. The public website

This GitHub Pages website publishes product information and policies. It contains no application analytics, advertising scripts, account forms or health-data upload features. GitHub provides the hosting and may process technical information such as IP addresses and request metadata under its own privacy statement.

2. Data used by the local application

When you connect your accounts, the local application processes:

  • Oura: authorized sleep and readiness records, including available sleep duration, sleep/readiness scores, overnight HRV and heart-rate measurements. The current MVP requests the daily OAuth scope.
  • Xunji: workout dates, exercises, weights, units, sets, repetitions, completion status, RPE and other fields returned in full workout records, which may include workout notes and heart-rate summaries. The current MVP does not request diet or body-measurement records.
  • Your entries: daily training/rest plans, energy, overall and per-muscle soreness ratings, exercise-classification preferences and model settings, training goals and availability, excluded movements or muscle groups, local fatigue and performance feedback, plan states, calibration history, free-text notes, and reports you generate.
  • Connection settings: the Xunji API key, Oura application credentials and OAuth tokens, and an OpenAI and/or Gemini API key and model ID if you enable optional AI interpretation.

3. Purpose and storage

Data is used to synchronize your records, calculate transparent training statistics and personal recovery baselines, display reports and save your check-ins. Runtime data and credentials are stored in a local directory on the computer running the app, separate from the source files by default. The directory is configurable with IRON_DATA_DIR; the default is work/iron-oura-data two levels above the application folder.

Local files are protected with filesystem permissions, but they are not encrypted by the application. Device access controls, backups and any storage location you choose remain relevant. The application does not intentionally publish private records or credentials to this website or the public source repository. The maintainer does not receive your local records merely because you use this self-run application.

4. External services and optional AI

The app sends account authorization and data requests to Oura and Xunji to operate the connections you enable. It does not sell personal data or include advertising trackers.

External AI interpretation is optional, with OpenAI or Google/Gemini selected in local settings. Only after you configure a key, select the relevant consent checkbox and request a report or send a chat message does the app send report context to the selected provider. For embedded chat, your question and the most recent six conversation rounds are also sent. Chat text may include whatever personal information you choose to enter; do not include credentials. That summary includes selected recovery values and baselines, recent training statistics, exercise/set details, derived muscle-workload estimates, training preferences, generated plans, local fatigue and performance feedback, the selected daily plan and numeric check-in ratings. It excludes connection secrets, free-text check-in notes, names and email addresses. Exercise names are included. Avoid putting sensitive unrelated information in exercise names.

OpenAI requests use store: false. Gemini uses its native API and its own data-processing terms; this OpenAI parameter is not applied to Gemini. Google unpaid-service terms instruct users not to submit sensitive or personal information, so this health-data application requires confirmation that the Gemini project uses paid services. See Google Gemini API terms. Switching provider clears consent and requires authorization naming the new recipient. Requests do not automatically fall back to another provider. This setting is not a promise of zero retention; OpenAI's applicable API terms, account settings and data controls govern its processing. Oura, Xunji and GitHub also process information under their own applicable terms and policies.

5. Retention, deletion and revocation

Local caches, check-ins, credentials, generated reports and chat histories remain until you delete them. Embedded chat histories are separated by report date; starting a new conversation archives the prior local history rather than deleting it. Chat does not automatically change saved plans or feedback. To remove local data, stop the application and delete its runtime data directory. Remove any exported reports and backups separately. Deleting the local directory does not delete records held by Oura or Xunji.

You can revoke this application's Oura access through your Oura account's connected-app controls and revoke or replace Xunji and OpenAI keys through their respective services. Removing a local token does not itself revoke provider-side authorization.

6. Your choices and questions

You choose which accounts to connect and whether to generate external AI reports. The current MVP does not write changes to your Oura or Xunji records. It may create or revise local training-plan drafts and local model candidates from your saved preferences and feedback, with accepted-plan revisions shown separately. For questions, corrections or assistance locating local data, contact dwy0618@gmail.com. Do not email API keys or complete health records.

7. Changes

If the app's data practices change, this policy will be updated with a new effective date. A cloud-hosted or multi-user version would require its own review of storage, access and deletion behavior before use.
